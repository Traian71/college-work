Lucrarea 5 – Implementarea algoritmilor paraleli. Sortarea. Recursivitate

Laborator Algoritmi Paraleli și Distribuiți – rezolvarea exercițiilor · File-Mitita Traian, 441A

Cele patru sortări sunt în același program (L5/Program.cs), cu codul din fișă. Programul sortează întâi vectorul de 64 de elemente din fișă cu toate cele patru variante, apoi verifică sortarea pentru mai multe lungimi și măsoară timpii. L-am rulat de două ori: cu valori între 0 și 42, ca în fișă, și cu valori între 0 și 999.999, pe macOS 26.7.2, Apple M2, 8 procesoare logice, .NET 8 Release, 27.11.2026 17:24. Fiecare timp este media a 3 rulări pe același vector de intrare. Înainte de măsurători fiecare sortare se rulează o dată nemăsurat, pentru că prima rulare după pornirea programului e mai lentă.

EXERCIȚIUL 1 – QuickSort serial

Am folosit QuickSort, Partition și Swap exact ca în fișă (pivotul este ultimul element al partiției). Pentru verificare, o funcție parcurge vectorul sortat și verifică că fiecare element e mai mic sau egal cu următorul:

public static bool EsteSortat(int[] m)
{
    for (int i = 0; i < m.Length - 1; i++)
    {
        if (m[i] > m[i + 1])
            return false;
    }
    return true;
}

Sortarea este corectă pentru toate lungimile încercate, inclusiv pentru cazurile limită cu 1 și 2 elemente.

EXERCIȚIUL 2 – QuickSort paralel

După prima partiționare, cele două părți se sortează în două threaduri, fiecare cu QuickSort serial, apoi se așteaptă cu Join:

public static void QuickSortPar(int left, int right)
{
    if (left < right)
    {
        int pivotIndex = Partition(left, right);

        // Create two threads to sort the left and right subarrays
        Thread leftThread = new Thread(() => QuickSort(left, pivotIndex - 1));
        Thread rightThread = new Thread(() => QuickSort(pivotIndex + 1, right));

        // Start the threads
        leftThread.Start();
        rightThread.Start();

        // Wait for the threads to finish
        leftThread.Join();
        rightThread.Join();
    }
}

Corectitudinea față de varianta serială: ambele variante pornesc de la o copie a aceluiași vector, iar o funcție compară element cu element rezultatul paralel cu cel serial. Rezultatul a fost identic la toate dimensiunile (egal cu serial: True).

EXERCIȚIUL 3 – MergeSort serial

Am folosit MergeSort și Merge ca în fișă; verificarea se face cu aceeași funcție EsteSortat, pe aceleași lungimi (partea MergeSort corect din ieșirea de la Exercițiul 1). Sortarea este corectă pentru toate lungimile. Spre deosebire de QuickSort, MergeSort împarte mereu vectorul la jumătate, deci nu depinde de valori: cu valori 0–42 a funcționat la fel de bine (chiar mai repede).

EXERCIȚIUL 4 – MergeSort paralel

Cele două jumătăți se sortează în două threaduri, iar după Join threadul principal face Merge:

public static void MergeSortPar(int l, int r)
{
    if (l < r)
    {
        int m = l + (r - l) / 2;

        // Create two threads to sort left and right sub-arrays
        Thread leftThread = new Thread(() => MergeSort(l, m));
        Thread rightThread = new Thread(() => MergeSort(m + 1, r));

        // Start the threads
        leftThread.Start();
        rightThread.Start();

        // Wait for the threads to finish
        leftThread.Join();
        rightThread.Join();

        Merge(l, m, r);
    }
}

Rezultatul a fost identic cu cel serial la toate dimensiunile.

  • Serial, QuickSort este mai rapid (64,53 față de 97,82 ms la N = 1.000.000): lucrează în același vector, pe când MergeSort alocă vectorii L și R la fiecare Merge.
  • Paralel, QuickSortPar a fost mai rapid (43,92 față de 53,14 ms), dar câștigul lui depinde de pivot. MergeSortPar are o accelerare mai stabilă, pentru că împarte mereu în două jumătăți egale.
